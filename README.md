# AmazingHand 손가락 1개 — 서보 ID 설정 (직접 실행용)

이 폴더의 스크립트는 지금까지 세션에서 실제로 동작 확인된 버전입니다. 여기부터는 본인이 직접 터미널에서 실행하세요.

## 0. 사전 준비 (한 번만)

```bash
python3 -m pip install rustypot numpy
```

## 1. 포트 확인

USB-TTL 어댑터가 꽂혀있는 상태에서:
```bash
ls /dev/cu.usbmodem* /dev/cu.usbserial* /dev/cu.wchusbserial* /dev/cu.SLAB* 2>/dev/null
```
나온 경로를 `scan_ids.py`와 `set_id.py` 안의 `PORT = "..."` 줄에 넣으세요 (지금은 `/dev/cu.usbmodem5B790178941`로 되어 있는데, 세션 중 확인된 값이라 재부팅/재연결하면 바뀔 수 있습니다 — 매번 `ls`로 재확인).

## 2. ⚠️ 가장 중요한 원칙

**한 번에 서보를 딱 하나만 버스에 연결한 상태에서 ID를 확인/변경하세요.**

두 서보가 같은 ID를 가진 채로 같이 연결돼 있으면:
- 읽기(read) 명령을 보내면 둘 다 동시에 응답해서 신호가 겹쳐 깨짐 → `Checksum error` / `Parsing error`가 반복해서 뜸
- 쓰기(write, 예: ID 변경) 명령을 보내면 **둘 다 동시에 명령을 받아서 실행**해버림 → 실수로 두 서보가 같은 새 ID로 바뀌어버리는 사고가 남 (이번 세션에서 실제로 이 문제가 발생했었습니다)

그러니 매 단계마다 **커넥터를 눈으로 보고 정말 하나만 꽂혀 있는지 확인**한 뒤 스크립트를 실행하세요.

## 3. 절차

### 3-1. 서보 A만 연결 → 현재 ID 확인
```bash
python3 scan_ids.py 1 2
```
- 결과에서 "성공 X/25"가 높게 나오는 ID가 이 서보의 현재 ID.
- 관측값이 **하나로만** 나오면 정상. 두 값이 섞여 나오면 서보가 2개 이상 연결된 것이니 다시 확인.

### 3-2. 필요하면 ID 변경
서보 A의 현재 ID가 1이면 그대로 두면 됩니다(이미 `ID_1`용). 만약 1이 아니면:
```bash
python3 set_id.py <현재ID> 1
```

### 3-3. 서보 A 분리 → 서보 B만 연결 → 현재 ID 확인
```bash
python3 scan_ids.py 1 2
```

### 3-4. 서보 B를 ID 2로 변경
```bash
python3 set_id.py <서보B_현재ID> 2
```
- `write_id` 실행 중 `Operation timed out`류 에러가 떠도 당황하지 마세요 — Feetech 서보는 쓰기 명령에 응답(ACK)을 안 보내는 경우가 흔해서, 실제로는 성공했는데 스크립트가 응답을 못 받아 타임아웃으로 보고하는 경우가 많습니다. `set_id.py`가 그 다음에 새 ID로 자동 재확인하니 그 결과를 믿으면 됩니다.

### 3-5. 최종 검증 — 서보 A + B 둘 다 연결
```bash
python3 scan_ids.py 1 2
```
기대 결과:
```
ID 1: 성공 XX/25, 실패 XX/25, 관측값 분포: {값1: XX}     -> 정상: 서보 1개만 응답 중
ID 2: 성공 XX/25, 실패 XX/25, 관측값 분포: {값2: XX}     -> 정상: 서보 1개만 응답 중
```
각 ID에서 **값이 하나로만** 나오면 성공입니다. 실패율이 0은 아니어도 괜찮습니다(이 버스 자체가 원래 통신이 좀 불안정한 편으로 확인됨) — 중요한 건 각 ID당 관측값이 하나로만 수렴하는지입니다.
